## Goal

Bind `PyMiliDatabase.query()` returning the upstream `QueryDict`
shape, bit-exact (dtype, shape, values, labels, states, times,
components, title, source) against upstream `mili` on the parity
corpus, single- *and* multi-fragment. Reuse M2's owned-`Vec` →
`into_pyarray_bound` zero-FFI-copy path; release the GIL around the
rayon gather (the contract's load-bearing case).

## The QueryDict shape (pinned — m1.md decision 2)

`datatypes.py:551-563`; upstream assembly `miliinternal.py:1165-1340`.
A plain constructed `dict` (not a `#[pyclass]`):

```
{ svar_name: {
    "class_name": str,
    "source":     "primal",          # M3 is primal-only
    "title":      str,               # svar.title
    "data":       np.ndarray,        # (n_states, n_labels, n_comps), svar dtype
    "layout": {
        "states":     np.int32[n_states],   # 1-based state numbers
        "labels":     np.int32[n_labels],   # entity labels
        "components":  List[str],
        "times":      np.float64[n_states],  # smaps[state-1].time
    },
    "modifier":   "",                # no ResultModifier in M3
} }
```

`data` dtype mirrors the svar numeric type
(`StateValues::{F32,F64,I32,I64}`). The
`tests/parity_support` Rust decoder already assumes exactly this dict
shape (m1.md decision 2), which de-risks it.

## In scope for M3

- **`PyMiliDatabase.query(svar_names, entity_type, *, labels=None,
  states=None, ips=None, **kwargs)`** — the primal path only. Accepts
  a single svar name or a list (upstream normalizes `str`→`[str]`);
  one class. Returns the `{svar: QueryDict}` dict above.
- **Single- and multi-state, single- and multi-svar** over the parity
  corpus (scalar / vector / array / vec-array svars the corpus
  actually exercises — same set the Rust `parity_corpus.rs` already
  proves bit-exact at the core layer).
- **Negative state indices** (`-1` = last) — upstream supports them
  (`README` query notes); normalize in the binding before the core
  call (core takes 0-based `&[usize]`).
- **`DatabaseSet` arm** via `DatabaseSet::query` → `SetQueryResult`
  (merged entity axis already parity-correct per status.md "Resolved:
  deferred query-merge parity gap").
- **Error mapping** through the existing `errors.rs` hierarchy
  (`UnknownSvar`/`UnknownClass`/`StateOutOfRange`/… →
  `MiliPythonError`).

## Out of scope (later milestones / known gaps)

- `as_dataframe`, `modifier` (ResultModifier), `write_data`,

## Resolved decisions (to settle before coding)

13. **`components` / `title` derivation → `mili-rs` core.** The
    component-name formatting is parity-sensitive
    (`miliinternal.py:1320-1336`: scalar→`[name]`, vector→component
    svar names, vec-array+ip→`f"{name} ipt. {ip_label}"`,
    array→`f"{name}[idx]"`). Per the M1/M2 precedent (core owns
    parity-sensitive string/ordering logic; the binding is a thin
    pass-through), core gains a single owned return that carries
    `values`, entity `labels`, `component_names`, `title`, and the
    numeric dtype — the binding only attaches `states`/`times` (from
    args + `times()`) and constructs the dict. Proposed:
    `Database::query_full` / `DatabaseSet::query_full` →
    `QueryResult { values, labels, components, title, class_name }`,
    with the existing `query`/`query_with_labels`/`SetQueryResult`
    primitives unchanged.

14. **Returned-array writability — re-evaluated for `query()`.** The
    m2.md decision 12 deferral lands here: upstream `data` is built by
    `np.empty(...)` then filled (writable), **not** `np.frombuffer`.
    So `IntoPyArray` (writable) matches; **no `.setflags`**. (The
    read-only `np.frombuffer` path the original m1.md question feared
    is not on upstream's `query()` assembly.) Confirm no upstream test
    mutates a returned `data` array in place (spot-checked: tests
    slice/compare; full grep at implementation).

15. **State-number / time layout.** `layout.states` = the normalized
    **1-based** state numbers (negative indices resolved);
    `layout.times` = `np.array([times()[s-1] for s in states])` —
    float64 (upstream builds it from Python floats). Asserted
    dtype-aware (exact int for states/labels/data, value-close for
    times).
