## What landed

- `PyMiliDatabase.query(svar_names, entity_type, *, labels=None,
  states=None, ips=None, **kwargs)` — primal path, returning the
  pinned upstream `QueryDict` shape (a plain Python dict, not a
  `#[pyclass]`): `{svar: {class_name, source, title, data,
  layout:{states,labels,components,times}, modifier}}`.
- Single- and multi-state / single- and multi-svar over the parity
  corpus; negative state indices normalised in the binding before
  the 0-based core call; `DatabaseSet` arm via
  `DatabaseSet::query` + `SetQueryResult`.
- Parity-sensitive `components` / `title` derivation moved into
  `mili-rs` core (new `Database::query_full` /
  `DatabaseSet::query_full` → `QueryResult { values, labels,
  components, title, class_name }`); the binding only attaches
  `states` / `times` and constructs the dict.
- `data` array writability: left writable
  (upstream builds it with `np.empty` + fill — already writable);
  the M2 read-only `np.frombuffer` deferral is closed.
- `layout.states` = normalised 1-based state numbers;
  `layout.times` = `float64`, built from `times()[s-1]`.
