## What landed

- `crates/mili-py/` PyO3 crate scaffold (`cdylib`, `#[pymodule]
  milox._native`, maturin build); PyPI dist + import package both
  `milox`; excluded from the default `cargo test --workspace` so the
  fast job never links pyo3 — dedicated `test-milox` CI job.
- `open_database()` Python shim (filename-root parsing /
  suffix-stripping) → `PyMiliDatabase` wrapping either
  `mili_rs::Database` or `mili_rs::DatabaseSet` chosen at open time
  by fragment count.
- Read-only **metadata** accessors only (no bulk arrays yet — M2/M3):
  `times`, `state_count`, `class_names`, `labels`, `state_maps`,
  `materials`, `material_numbers`, `element_sets`,
  `integration_points`, `mesh_dimensions`.
- Error mapping (`errors.rs`): `MiliError` → the three-class Python
  hierarchy (`MiliFileNotFoundError` / `MiliAParseError` /
  `MiliPythonError`) with typed detail preserved in the message.
- Four corpus-driven parity fixes in the `mili-rs` core (class_names
  per-mesh, element_sets key, labels ident-class fallback, the
  per-accessor DatabaseSet reduction map).
